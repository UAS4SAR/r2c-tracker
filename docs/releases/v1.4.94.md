# v1.4.94 — managed pilot request follow-up

- Platform administrators can create an organization and send its invitation from a request, resend activation or access emails, and close, decline, or reopen requests with an audited note.
- Requests display linked organization activation status. Existing requests are reconciled using both designator and primary administrator email; unrelated requests sharing a designator cannot send invitations or create duplicate organizations.
- Request links survive administrator replacement. Resending after a replacement's initial email fails sends activation to the current administrator rather than an ordinary login email.
- Closing or declining a request does not archive or otherwise alter its organization. Database changes are additive and retain original request details and acknowledged terms.

## Validation

- Full local qualification passed: 427 tests, HTTP and organization-scoped coordination checks, migration compatibility, dependency vulnerability audit, static security analysis, secret scan, and SBOM.
- Isolated PostgreSQL runtime checks passed for database recovery, retention, concurrent tenant coordination, authenticated uploads, tenant denial, duplicate rejection, and isolated archives.
- Additional disposable PostgreSQL checks verified concurrent duplicate requests create exactly one organization and that upgrading the legacy request schema preserves submissions and links matching organizations.
- Synthetic browser review verified pending, awaiting-activation, activated, and closed states, creation confirmation, and close/decline note controls. No live request or organization was changed during implementation.
